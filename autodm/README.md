# 캐롤DM — 인스타그램 댓글 자동 DM 매니저 (SEED Design)

인스타그램 게시물에 댓글이 달리면 자동으로 DM을 보내는 **셀프 호스팅 앱**이에요.
인포크매니저 가이드(신·구버전 자동 DM, 템플릿, 자동화 관리, 설정, 댓글 추첨, 발송 실패 FAQ)에 나온 자동 DM 기능을 모두 구현했고,
화면은 당근 **SEED Design**(`@seed-design/react` + 공식 스니펫)으로 만들었어요.

- **PC에서 바로 실행** — `npm run dev` 한 번이면 끝. 데이터는 내 PC의 `data/db.json`에 저장돼요.
- **데모 모드** — Meta 앱 없이도 가상 계정·게시물·팬으로 모든 기능을 체험하는 시뮬레이터가 들어 있어요.
- **실제 연동** — Instagram API(Instagram 로그인) + 웹훅으로 실제 계정의 댓글에 DM을 보내요.
- **앱 확장 준비** — 반응형 화면(PC는 사이드바·다이얼로그, 좁은 화면은 하단 탭·바텀시트).

---

## 1. 빠른 시작 (데모)

필요한 것: [Node.js](https://nodejs.org) 20.19 이상 (22 LTS 권장)

```bash
cd autodm
npm install
npm run dev
```

브라우저에서 **http://localhost:5173** → **데모로 시작하기**.
왼쪽 메뉴의 **시뮬레이터**에서 팬이 되어 댓글을 달고, 받은 DM의 버튼을 눌러 보세요.

| 명령 | 설명 |
| --- | --- |
| `npm run dev` | 개발 모드 (API 서버 :8787 + 화면 :5173, 코드 수정 시 자동 반영) |
| `npm run build` → `npm start` | 배포 모드 — 화면과 API를 **한 포트(:8787)** 로 제공 |
| `npm test` | 자동화 엔진·웹훅 테스트 |
| `npm run typecheck` | 타입 검사 |

## 2. 기능 (인포크매니저 신버전 가이드 대응표)

| 가이드 항목 | 캐롤DM |
| --- | --- |
| 인스타그램 연동/해지 | 약관 동의 → Instagram 로그인(권한 5종) → **연동된 계정 확인(맞아요/다른 계정)** → 완료. 다시 연동(`force_reauth`), 해지 시 자동화·기록 삭제 |
| 1. 새로워진 홈 | 성과 요약(보낸 DM·읽음·클릭·클릭률), **최근 7일 추이**, 게시물별로 묶인 자동화(게시물 순/최신 순), 내 템플릿·이벤트 추첨 바로가기, 일시 중지 표시, 처음 들어오면 **둘러보기** |
| 2. 자동 DM 설정 | **게시물 → 템플릿 → 최종 확인** 세 단계, 진행 막대, 확인한 단계는 한 줄 요약으로 접힘, 나가려 하면 “만들던 자동화를 나갈까요?” |
| 2-1. 게시물 선택 | 올린 게시물에서 고르기 / **다음에 올릴 게시물에 적용**(새 게시물에 첫 댓글이 달리면 연결, 1개만 · 한 번에 하나만) |
| 2-2. 템플릿 선택 | 미리보기(추가 기능 목록 포함), 내 템플릿 먼저 + ⋯ 수정·삭제, 템플릿 추가 후 자동 선택, 기본 템플릿 9종 + 추천 표시 |
| 2-3. 어떤 댓글에 | 모든 댓글(게시물당 1개) / 키워드 댓글(문장 안 포함 일치, 쉼표·엔터·＋로 칩, 200자, 키워드 아이디어, “이미 넣은/이미 이 게시물에 걸린 키워드예요”) |
| 2-4. 팬이 받을 DM | 팬 댓글 → “자동으로 DM을 보내요” → 말풍선. **말풍선·버튼(연필)을 눌러 바로 수정**, 640자, 버튼 3개(이름 20자, 주소 붙여넣기/내 링크에서 고르기), 링크 없는 버튼은 “링크 설정 안 됨”으로 막음 |
| DM 전체 편집하기 | 편집 + 실시간 미리보기 두 칸, 텍스트 / **이미지 캐러셀**(카드 10장, 이미지 올리기·주소, 제목·설명 60자, 버튼 3개, 링크로 카드 채우기, **끌어서 순서 바꾸기**) |
| 2-5. 팔로워 확인 후 보내기 | 팔로우 확인 / 팔로워 / 비팔로워 탭(완료 표시), 확인 버튼은 이름만 수정, 비팔로워 DM에 다시 확인 버튼 자동 추가, 캐러셀은 팔로워 DM에서만 |
| 2-6. 추가 기능 | 댓글 답글(10·20·30개, 정중하게·친근하게·**내 답글 3~30개 + 답글 모음 저장/불러오기**), DM 공유에도 답하기, DM 코드에도 답하기(**영문·숫자 4자리, 등록 전에 미리 보여 주고 안내 문구 복사**) |
| 2-7. 즉시·예약·일괄 | 고른 방식이 펼쳐지며 안내 / 예약(빠른 선택 + **시간 휠**, 30분 단위·7일 이내, 보낸 뒤 새 댓글에도) / 일괄(최근 7일, 이미 받은 댓글 제외, 끝나면 즉시 발송). **같은 사람에게는 한 번만**. 등록 중 → “자동화를 등록했어요” → 템플릿이 없으면 “템플릿으로 만들어 볼까요?” |
| 3. 템플릿 | 템플릿 N개·최대 50개, 자주 쓴 순/최근 순, 3단계 만들기(공통 설정 → DM 쓰기 → 이름 “내 템플릿 N”·댓글에서/DM에서 미리보기), 방금 만든 자동화로·자주 쓰던 DM으로 만들기 |
| 4. 자동화 관리 | 스위치(“자동화를 켰어요/껐어요”), 상세: 상태·전송/읽음/클릭(세는 방법)·**최근 24시간 발송 상태와 실패 이유**·DM 공유/코드 토글·코드 복사·안내 문구, 수정(“N곳을 바꿨어요”, 즉시 발송은 게시물 바꾸기), 복제(게시물만 다시 고르기), 삭제(기록은 남음), 순차 발송중 |
| 5. 설정 | DM 자동 발송·댓글 자동 답글 일시 중지 / 모두 다시 켜기, 발송 속도·안전 장치, 공개 주소, 도움말(둘러보기·이용 가이드·DM 발송 문제·연동 문제) |
| 6. 댓글 자동 추첨 | 게시물(댓글 수) → 조건·인원 → 결과, 한 사람 1회, 발표 글 복사·공유, 다시 뽑기, 게시물별 지난 추첨 |
| 링크 블록에서 바로 설정 | **내 링크** → “자동 DM 만들기” → 그 링크를 안내하는 설정 제안 → 이대로 등록/직접 수정 |

가이드에 있지만 넣지 않은 것: 유료 이용권·무료 체험(셀프 호스팅이라 필요 없음), 신버전/구버전 화면 전환(신버전만 제공).

### 인플루언서 안전 기능 (KittyChat 인플루언서 기능 대응)

| 기능 | 캐롤DM |
| --- | --- |
| DM 문구 변형 | 원래 문구 + **다른 문구 최대 5개** → 팬마다 하나를 골라 보내요(같은 팬은 늘 같은 문구). 똑같은 DM을 반복하지 않아 스팸 감지에 덜 걸려요 |
| AI로 다른 문구 만들기 (선택) | `.env`에 `ANTHROPIC_API_KEY`가 있으면 **AI로 만들기** 버튼이 보여요. 뜻·말투는 그대로, 링크와 `{이름}`은 글자 그대로 두고 표현만 바꿔요(빠진 결과는 버려요) |
| `{이름}` 개인화 | 문구에 `{이름}`(또는 `[username]`)을 넣으면 받는 팬의 인스타그램 아이디로 바뀌어요. 미리보기에서도 바뀐 모습으로 보여요 |
| 발송 속도 | 설정 › **발송 속도 · 안전 장치**: 시간당 최대 DM 수, **DM 고르게 나눠 보내기**(한도에 맞춰 간격), **답글 간격**(예: 20~60초 사이 무작위), 시간당 최대 답글 수 |
| 제한 신호 사전 경고 | 인스타그램이 발송 제한(한도 초과·일시 차단 등)으로 응답하면 신호로 세요(10분 안의 반복은 1번). **1~2번: 답글을 10분에 하나씩**, **3번: 댓글 답글 자동 멈춤**(DM은 계속). 홈·설정에 경고가 뜨고, 괜찮아지면 “기록 지우기” |
| 메일 알림 (Gmail) | 설정 › **메일 알림**에 Gmail 주소와 **앱 비밀번호(16자리)**를 넣으면 제한 신호 1·2·3번째, 답글 자동 멈춤, **인스타그램 연결 끊김**을 메일로 보내요(3번째 뒤로 신호가 계속되면 3시간에 한 번). 테스트 메일 버튼, `.env`의 `GMAIL_USER`·`GMAIL_APP_PASSWORD`·`ALERT_EMAIL_TO`로도 설정 가능. 앱 비밀번호는 서버에만 저장하고 화면·API에는 내보내지 않아요 |
| 단체 DM | **최근 24시간 안에 나에게 DM을 보내거나 버튼을 누른 팬에게만** 한 번에 보내요. 대상·남은 시간 표시, 보내기 직전에도 24시간을 다시 확인해서 지난 팬은 건너뛰어요. 시간당 한도 안에서 순서대로 보내요 |

**만들지 않은 것** (인스타그램 정책 위반이라 넣지 않았어요): 24시간이 지난 팬에게 보내는 브로드캐스트, 반응하지 않은 사람에게 보내는 콜드·대량 DM, 새 팔로워 환영 DM, 상담원(human agent) 태그를 이용한 24시간 우회, 댓글 하나에 비공개 답장 여러 번, 24시간을 넘기는 시퀀스, 연락처 가져오기, 댓글 좋아요(공식 API에 없음).

**집계 기준** — 전송: 실제로 보낸 DM 수(팔로우 확인 DM 포함) · 읽음: DM을 연 사람 수 · 클릭: 버튼 클릭 횟수(팔로우 확인 버튼 제외).
버튼 링크는 `/r/<발송ID>/<버튼ID>` 추적 링크로 나가요. 보낼 때의 링크를 기록해 두어서 자동화를 고치거나 지워도 이미 보낸 버튼은 그대로 동작해요.

## 3. 실제 인스타그램 연동

> 데모로 충분히 익힌 뒤 진행하세요. 인스타그램 **프로페셔널(크리에이터·비즈니스) 계정**이 필요해요.

1. **Meta 개발자 앱 만들기** — [developers.facebook.com](https://developers.facebook.com/apps) → 앱 만들기 → Instagram 제품 추가 → *API setup with Instagram login*.
   권한: `instagram_business_basic`, `instagram_business_manage_messages`, `instagram_business_manage_comments`, `instagram_business_content_publish`, `instagram_business_manage_insights`
2. **공개 HTTPS 주소 만들기** — 인스타그램 로그인과 웹훅은 HTTPS가 필요해요. PC에서는 터널을 써요.
   ```bash
   npm run build && npm start              # :8787 에서 화면+API
   cloudflared tunnel --url http://localhost:8787   # https://xxxx.trycloudflare.com 발급
   ```
3. **`.env` 채우기** (`.env.example` 복사)
   ```env
   IG_APP_ID=…            # Instagram 앱 ID
   IG_APP_SECRET=…        # Instagram 앱 시크릿
   WEBHOOK_VERIFY_TOKEN=아무거나-직접-정한-문자열
   PUBLIC_BASE_URL=https://xxxx.trycloudflare.com
   ```
   서버를 다시 켜면 **설정 › 공개 주소**에 넣을 주소들이 보여요.
4. **Meta 앱에 주소 등록**
   - OAuth 리디렉션 URI: `https://xxxx.trycloudflare.com/auth/instagram/callback`
   - 웹훅 콜백 URL: `https://xxxx.trycloudflare.com/webhooks/instagram`, 확인 토큰: `WEBHOOK_VERIFY_TOKEN`
   - 웹훅 필드: `comments`, `messages`, `messaging_postbacks`, `messaging_seen`
5. 앱의 **연동·계정 → 인스타그램 연동하기**. 권한 화면에서 **모두 허용**해 주세요.

**알아 두세요**
- Meta 앱이 *개발 모드*일 때는 앱에 역할(관리자·테스터)로 등록된 계정의 이벤트만 받아요. 다른 사람 댓글에 반응하려면 앱 검수(고급 액세스)와 *라이브 모드*가 필요해요.
- 이 앱이 꺼져 있으면 웹훅을 못 받아요. **PC가 켜져 있는 동안만 DM이 나가요** → 24시간 운영은 아래 4번처럼 서버로 옮기세요.
- 인스타그램 정책: 댓글 비공개 답장은 댓글 하나당 1번·7일 이내, 버튼을 누르거나 DM을 보낸 사람에게는 24시간 안에 추가로 보낼 수 있어요(팔로우 확인이 버튼을 쓰는 이유). 계정별 발송 한도를 넘는 만큼은 대기열에 두고 순차 발송해요.
- 토큰(60일)은 서버가 만료 7일 전에 자동 갱신해요. 다른 자동 DM 서비스가 연결돼 있으면 먼저 해제하세요.

### 관리 화면 보안

- 서버는 기본으로 **이 PC(127.0.0.1)에서만** 열려요. 같은 와이파이의 휴대폰에서도 열고 싶으면 `.env`에 `HOST=0.0.0.0`.
- **이 PC의 브라우저(localhost)** 에서는 로그인 없이 쓸 수 있어요.
- **터널 주소나 다른 기기**에서 관리 화면을 열면 **관리자 비밀번호**로 로그인해야 해요. 비밀번호는 서버를 켤 때 콘솔에 보이고, 이 PC에서 **설정 › 관리자 비밀번호**로도 보거나 새로 만들 수 있어요(새로 만들면 바깥에서 로그인한 브라우저는 모두 로그아웃). 직접 정하려면 `.env`의 `ADMIN_PASSWORD`.
- 웹훅(`/webhooks/instagram`)은 Meta 서명(X-Hub-Signature-256)으로, 버튼 클릭 추적(`/r/…`)은 누구나 열 수 있는 링크로 동작해요 — 로그인이 필요 없어요.
- 비밀번호를 1분에 5번 넘게 틀리면 잠시 막혀요. 다른 웹사이트가 몰래 설정을 바꾸는 요청(CSRF)도 막아 두었어요.

## 4. 나중에 앱으로 만들 때

- **화면**: 이미 반응형이에요(768px 미만에서 하단 탭, 다이얼로그는 바텀시트). [Capacitor](https://capacitorjs.com)로 `dist/`를 감싸면 iOS·Android 앱이 되고, 더 네이티브한 화면 전환이 필요하면 SEED의 Stackflow 연동(`@seed-design/stackflow`)으로 옮기면 돼요.
- **서버**: 앱은 화면일 뿐이고, 웹훅을 받는 `server/`는 항상 켜진 곳(클라우드 VM·컨테이너)에 두어야 해요. `npm run build && npm start` 그대로 올리면 되고, 사용자가 많아지면 `server/store.ts`(JSON 파일)를 DB로 바꾸세요 — 저장소 접근이 한 곳에 모여 있어요.
- SEED 컴포넌트 추가: `npx @seed-design/cli@latest add ui:<이름>` (스니펫은 `seed-design/ui/`).
